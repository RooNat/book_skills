# 市场失败律先验

## R — 原文 (Reading)

> 大多数新产品都将在市场上遭遇失败，即使所有的方案都被执行到位也不能避免。
>
> — Alberto Savoia, 第1章「市场失败律」

---

## I — 方法论骨架 (Interpretation)

评估新创意时, 不要把成功当作默认结果, 也不要把失败当作异常事故。
这套方法把失败设为初始先验: 一个未经验证的新产品大概率会失败。
强团队、好设计、充足资金和漂亮计划只能说明执行能力, 不能证明市场会买账。
因此, agent 的第一步不是帮用户完善路线图, 而是问: 现在有什么证据足以抵消这个负先验?
证据必须逐步从意见、计划和二手数据升级为目标市场的行为数据。
只有当多轮证据持续支持创意时, 才能把它从“高失败风险”移动到“值得继续下注”。

## A1 — 书中的应用 (Past Application)

### 案例 1: 新可乐与水晶百事
- **问题**: 顶级消费品公司拥有品牌、渠道、调研和执行能力, 仍推出失败新品。
- **方法论的使用**: 作者用这些案例说明市场失败律不会因为公司强大而失效。
- **结论**: 大公司失败不是例外, 而是新产品默认风险的证据。
- **结果**: 新可乐被迫恢复传统配方, 水晶百事也成为失败案例。

### 案例 2: 谷歌 Wave
- **问题**: 谷歌具备优秀工程和产品人才, 仍有新产品撞上市场失败律。
- **方法论的使用**: 作者提醒读者不要用公司能力替代市场证据。
- **结论**: 执行到位也可能只是把错误创意更快推向失败。
- **结果**: 谷歌 Wave 推出后数月即宣布逐步下线。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户准备推进一个新产品、新功能、新服务、新业务, 但主要理由是“我们能做好”。
2. 用户拿团队履历、融资、资源、品牌或执行计划来证明市场会接受。
3. 用户问“这个想法不错, 怎么落地?”但还没有市场行为证据。
4. 用户在复盘失败时只讨论执行问题, 没有讨论前提风险。

### 语言信号

- “我们团队很强, 应该能做成”
- “只要执行到位就会成功”
- “这个市场这么大, 我们先做出来”
- “我们已经有资源/渠道/投资人了”

### 与相邻 skill 的区分

- 与 `right-it-diagnosis` 的区别: 本 skill 用于重设风险先验; `right-it-diagnosis` 用于具体判断失败属于启动、运营还是前提。
- 与 `escape-thoughtland` 的区别: 本 skill 处理过度乐观的起点; `escape-thoughtland` 处理证据质量问题。

## E — 可执行步骤 (Execution)

1. **声明失败先验**
   - 完成标准: 明确写出“未经验证的新创意默认高失败风险”, 并列出用户当前证据属于计划、能力、意见还是行为。

2. **拆分成功所需关键条件**
   - 完成标准: 至少列出市场需求、触达、使用/购买、交付、留存或复购等关键条件。
   - 判停条件: 若市场需求条件没有证据, 先转向 `escape-thoughtland` 或 `xyz-hypothesis`。

3. **要求抵消先验的证据**
   - 完成标准: 给出下一步需要收集的 2-3 类 YODA, 并说明每类证据能降低哪种失败风险。

4. **给出当前下注建议**
   - 完成标准: 用“继续探索 / 小额测试 / 暂停大投入 / 可进入下一阶段”之一收尾。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户只是在查询已上市产品的客观信息, 不涉及新创意判断。
- 产品已有长期真实收入、留存和复购数据, 当前问题只是局部优化。
- 用户已经明确要求生成试验方案, 此时应调用更具体的 `pretotype-yoda`。

### 作者在书中警告的失败模式

- 把强执行力当作市场失败的解药。
- 用品牌、融资、团队履历替代目标市场的行为证据。
- 失败复盘时互相指责, 却不承认产品前提可能错误。

### 作者的盲点 / 时代局限

- 对高监管、长周期 B2B、公共部门和基础科研等场景, 市场先验仍重要, 但不能只用早期市场反应判断价值。
- 生成式 AI 降低了原型成本, 但低成本构建不等于市场先验消失。

### 容易混淆的邻近方法论

- `right-it-diagnosis`: 用于失败归因和 go/no-go 分支。
- `tri-meter`: 用于多轮试验后的证据综合, 不是初始先验设定。
