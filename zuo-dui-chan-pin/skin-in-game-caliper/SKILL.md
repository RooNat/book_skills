# 用切身利益卡尺校准证据强度

## R — 原文 (Reading)

> 切身利益卡尺：帮助你量化和校准切身利益的工具，很有必要，因为并非所有的切身利益都一样。
>
> — Alberto Savoia, 第6章「切身利益卡尺」

---

## I — 方法论骨架 (Interpretation)

不是所有反馈都同样有价值。
意见、点赞、浏览、评论几乎没有切身利益, 只能代表注意力或礼貌。
邮箱、电话、预约、到场、数据导入、订金、付款都要求用户付出代价, 因此证据更强。
切身利益卡尺不是精确科学, 而是防止团队把弱信号当强信号。
agent 应把反馈按代价排序, 再判断这些代价是否来自目标市场和目标行为。
越接近真实购买、真实使用和真实损失, 证据越能支持“正确的它”。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: Tortell-o-matic
- **问题**: 团队需要判断用户是否真的会买一台自动意面机。
- **方法论的使用**: 作者用不同承诺层级说明意见、联系方式、订金等证据强度不同。
- **结论**: 只有付出真实代价的反馈才接近购买证据。
- **结果**: 卡尺成为后续 YODA 解释工具。

### 案例 2: 谷歌眼镜
- **问题**: YouTube 热度和申请热情很高, 但是否代表长期需求不确定。
- **方法论的使用**: 1500 美元付款和到指定城市培训比观看视频强, 但仍需长期使用数据。
- **结论**: 切身利益有强弱, 初期付款也不等于留存。
- **结果**: 谷歌眼镜探索者热度退去后项目取消。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户拿到多种市场反馈, 不知道哪种更可信。
2. 用户把点赞、浏览、评论当作需求证据。
3. 用户想判断邮箱、预约、订金、付款哪个更能支持继续投入。
4. 用户需要把预型数据整理成证据等级。

### 语言信号

- “这些数据算不算有需求?”
- “点赞很多, 能证明吗?”
- “多少邮箱/订金才算强信号?”
- “怎么评估用户反馈质量?”

### 与相邻 skill 的区分

- 与 `escape-thoughtland` 的区别: 本 skill 处理已经有行为数据后的强弱校准。
- 与 `tri-meter` 的区别: 本 skill 评价单次或单类证据强度; TRI 综合多轮试验方向。

## E — 可执行步骤 (Execution)

1. **列出所有反馈**
   - 完成标准: 将浏览、点击、评论、邮箱、预约、试用、订金、付款等分项列出。

2. **标注切身利益类型**
   - 完成标准: 对每项标注用户付出的金钱、时间、身份、数据、声誉或机会成本。

3. **按证据强度排序**
   - 完成标准: 从弱到强排列, 并说明哪些不能算合格 YODA。

4. **判断是否足以支持假说**
   - 完成标准: 对照 xyz 中的 Z, 判断实际行为是否匹配目标行为。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户只有意见、访谈和专家判断, 先调用 `escape-thoughtland`。
- 用户要设计试验而非分析结果, 先调用 `pretotype-yoda`。
- 需要综合多轮试验后做 go/no-go, 调用 `tri-meter`。

### 作者在书中警告的失败模式

- 没有切身利益的支持。
- 把浏览量、点赞和评论当作购买证据。
- 对早期热度过度解释。

### 作者的盲点 / 时代局限

- 对免费产品、开源工具或公共服务, 金钱不是唯一切身利益, 需要重视时间、数据迁移、组织承诺等。
- 隐私法规下, 收集联系方式和数据本身需要明确授权。

### 容易混淆的邻近方法论

- `tri-meter`: 汇总多次试验。
- `adjust-before-pivot`: 在证据不理想后决定怎么改。
