# 设计预型试验收集 YODA

## R — 原文 (Reading)

> 预型所解答的则是一个更根本的问题：“我们是否应该构建它？”
>
> — Alberto Savoia, 第5章「预型工具」

---

## I — 方法论骨架 (Interpretation)

预型不是低保真原型, 它要回答的问题不同。
原型问“能不能做出来”, 预型问“市场是否值得我们做出来”。
一个合格预型应当快速、便宜, 并能让目标市场付出切身利益。
它可以是人工伪装、假门、视频、临时服务、改标签或潜入真实销售环境。
重点不是骗过所有人, 而是在合规和伦理边界内模拟关键市场交互。
输出应是 YODA: 当前团队从当前目标市场收集的一手行为数据。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: IBM 语音转文本
- **问题**: 真正做出语音转文本机器成本极高。
- **方法论的使用**: IBM 用隐藏打字员模拟机器, 让用户像使用真产品一样体验。
- **结论**: 用户真实体验后发现噪声、隐私和效率问题。
- **结果**: IBM 避免了对错误前提的大投入。

### 案例 2: CarsDirect
- **问题**: 团队尚无库存和完整运营, 但想验证用户是否会线上买车。
- **方法论的使用**: 先上线可购买网站, 有订单后人工去经销商买车交付。
- **结论**: 用户愿意付出高额真实付款。
- **结果**: 4 个订单证明需求, 团队再正式构建公司。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户想验证需求, 但产品还没做出来。
2. MVP 或原型成本高, 风险大。
3. 用户在问“是否值得做”, 而不是“怎么做出来”。
4. 已有 xyz 假说, 需要设计市场行为试验。

### 语言信号

- “我们还没有产品, 怎么验证?”
- “MVP 太贵了”
- “怎么知道用户会不会买?”
- “先做原型还是先测需求?”

### 与相邻 skill 的区分

- 与 `pretotype-technique-selection` 的区别: 本 skill 设计预型试验整体; 技术选择 skill 负责在多种预型类型中挑方案。
- 与 `skin-in-game-caliper` 的区别: 本 skill 收集数据; 卡尺 skill 评估数据强弱。

## E — 可执行步骤 (Execution)

1. **确认要回答的问题**
   - 完成标准: 明确问题是“是否应该构建”, 而不是技术可行性。

2. **绑定 xyz 假说**
   - 完成标准: 写出本次试验要验证的 x、y、z。
   - 判停条件: 若没有 xyz, 先调用 `xyz-hypothesis` 或 `hypozoom-to-xyz`。

3. **设计最小市场交互**
   - 完成标准: 说明用户会看到什么、做什么、付出什么切身利益。

4. **检查预型三条件**
   - 完成标准: 快速、便宜、产生带切身利益 YODA 三项都满足。

5. **定义记录表**
   - 完成标准: 列出样本量、行为数、转化率、成本、异常记录和伦理告知方式。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 核心风险是技术不可行, 应做原型或技术验证。
- 试验涉及医疗、安全、金融等高风险承诺且无法合规告知。
- 用户已经收集完试验数据, 应调用 `skin-in-game-caliper` 或 `tri-meter`。

### 作者在书中警告的失败模式

- “只要我们建成了, 用户就会被吸引过来”。
- 把普通调研当成预型。
- 预型无法产生切身利益 YODA。

### 作者的盲点 / 时代局限

- 生成式 AI 让某些预型可直接变成可用原型, 但仍要区分市场验证和技术验证。
- 假门、假面等方式在今天需要更谨慎处理透明度、隐私和用户补偿。

### 容易混淆的邻近方法论

- `pretotype-technique-selection`: 选择具体预型类型。
- `tri-meter`: 多轮试验后做决策综合。
